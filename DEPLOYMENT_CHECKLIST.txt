STEP 1: Clean & Rebuild
═════════════════════════

Run the deployment script:
  ./redeploy.sh

Or manually:
  1. Kill Metro bundler:
     lsof -ti:8081 | xargs kill -9

  2. Start Metro with cache reset:
     npx react-native start --reset-cache

  3. In NEW terminal, build app:
     iOS:     npx react-native run-ios
     Android: npx react-native run-android

STEP 2: Test Playbook Generation
═══════════════════════════════════

□ Navigate to playbook generation screen
□ Create a new playbook
□ Verify it completes successfully
□ If error occurs, check message is friendly (no "circuit breaker")
□ Check console for health monitoring logs (dev mode)

STEP 3: Test Devotional Generation
═══════════════════════════════════

□ Open devotional modal from any playbook
□ Test 1-day devotional
□ Test 3-day devotional
□ Test 5-day devotional
□ Test 7-day devotional
□ Verify all complete successfully
□ If error occurs, check message is friendly

STEP 4: Verify Error Messages
═══════════════════════════════

If circuit breaker opens (unlikely):
□ Error should say: "We're experiencing high demand right now. 
   Please try again in a few moments."
□ Should NOT show: "Circuit breaker is OPEN for openai generation"
□ Should NOT show any technical error messages

STEP 5: Check Health Monitoring
═══════════════════════════════

In dev mode, check console for:
□ Health monitoring logs every 60 seconds
□ Circuit breaker state (should be CLOSED)
□ Queue size (should be low during testing)
□ Success rate (should be high)

To manually check:
  import { logSystemHealth } from './src/utils/healthMonitoring';
  logSystemHealth();

Enable Health Monitoring in App.tsx:
═══════════════════════════════════════

Add this code to your App.tsx:

  import { startHealthMonitoring } from './src/utils/healthMonitoring';
  
  function App() {
    useEffect(() => {
      if (!__DEV__) {
        const stopMonitoring = startHealthMonitoring(60000);
        return () => stopMonitoring();
      }
    }, []);
    
    // ... rest of your app
  }
